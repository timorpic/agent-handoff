# AGENTS.md（局部作用域模板）

> 放在模块根目录 `<MODULE_PATH>/AGENTS.md`，只补充本模块专属规则。
> 复制本模板到目标模块后，把 `<MODULE_PATH>`、`<MODULE_NAME>` 替换为实际值。

## 作用域

- 本文件的位置：`<MODULE_PATH>/AGENTS.md`，模块名：`<MODULE_NAME>`。
- 只适用于 `<MODULE_PATH>` 及其子目录；离开该目录后按上层的规则执行。
- 上层 AGENTS.md 与 [docs/AGENT-RULES.md](../../docs/AGENT-RULES.md) 仍然适用，
  本文件只补充模块差异，不覆盖也不放宽上层规则。
- 本模板正文里的 `../../docs/AGENT-RULES.md` 按「模块目录距仓库根两级」写成
  （如 `src/api/`）。复制到其他深度必须改写：顶层模块（`api/`）用 `../docs/`，
  `src/a/b/` 用 `../../../docs/`。深度写错时通常表现为断链，
  但若错误位置上恰好存在同名文件，会静默指向别的文件而不报错，复制后当场核对一次。

## 与上层的关系

读取顺序：仓库根 AGENTS.md → 本文件 → 本模块相关正式文档。
两边冲突时，以限制更严格的一方为准；无法判断时先核实再改，不按文件新旧取舍。

## 同级工具入口

同级的 `CLAUDE.md` 应指向本文件而不是复制内容，保持薄壳：

~~~markdown
# CLAUDE.md（<MODULE_NAME>）

读取本目录 AGENTS.md，并沿上层入口读取根目录 AGENTS.md 与 docs/AGENT-RULES.md。
本文件不复述规则正文。
~~~

其他具备原生规则入口的工具同理：入口只定向到本文件，正文只维护一份。
目录或模块改名时同步更新 `<MODULE_PATH>` 与本文件的链接，不留下断链。
