# Agent Handoff

用于 Codex、Claude Code 等编程工具之间的任务接力的通用项目模板。
一个工具额度耗尽或中途停止后，由用户切换到另一个工具，依据项目文件继续工作。

共享规则、长期知识、任务目标、检查点与验证记录；人工切换工具，不自动调度 Agent。
模板不预设业务、技术栈或部署平台，不携带具体项目的历史。

## 一键初始化

进入你的项目文件夹，运行：

```bash
curl -fsSL https://raw.githubusercontent.com/timorpic/agent-handoff/HEAD/scripts/bootstrap.sh | bash
```

需要 Bash、curl、tar 和常见系统工具，初始化不依赖 Git 或 Node.js。
始终初始化当前目录，已有同名文件会导致停止；已有 README.md 保留，不影响安装其他文件。
没有 README.md 时生成空白项目说明，不把本页复制进项目。

也可以先下载脚本，预览后初始化：

```bash
curl -fsSL https://raw.githubusercontent.com/timorpic/agent-handoff/HEAD/scripts/bootstrap.sh -o /tmp/agent-handoff-bootstrap.sh
bash /tmp/agent-handoff-bootstrap.sh --dry-run
bash /tmp/agent-handoff-bootstrap.sh
```

初始化后填写项目需求和说明，未知信息保留待填写，没有实际任务时保持 draft。

## 如何进行任务接力

日常操作是：**旧工具保存进度 → 停止旧工具写入 → 新工具读取记录并接手**。
在同一个项目文件夹中切换工具，不需要复制聊天记录，也不需要每次重新安装模板。
不要让两个工具同时修改项目；助手中的 owner 和认领记录不是真正的锁。

### 第一次开始任务

初始化后文件仍是空白模板。把实际需求交给当前工具，并附上：

```text
先读取 AGENTS.md 及其要求的规则，核实当前项目身份与已有修改。
根据我本次的实际需求填写任务上下文、验收标准和首份检查点；未知信息保留未知，不虚构历史。
先完成接管记录，再开始修改业务代码；每完成一个可恢复的小步骤，保存进度和验证结果。
如提供 scripts/handoff.mjs，按 docs/HANDOFF-HELPER.md 使用助手；否则按 HANDOFF.md 维护记录。
```

没有实际任务时保持 draft，不用为了安装模板而虚构一个任务。

### 正常切换工具

**1. 在旧工具中发送：**

```text
准备交接当前任务。请核对实际文件与验证结果，保存未完成工作和下一步，保留我的所有修改。
如提供接力助手，按说明准备完整结果，用 save 和一个全新 handoff_id 保存交接，再用 prompt 生成接管提示。
否则按 HANDOFF.md 保存检查点并生成接管提示。不得把未执行的验证标成通过。
交接保存后停止继续写入；不提交、不推送、不发布。
```

**2. 确认旧工具及其派生任务已停止写入，然后打开新工具。**

**3. 把生成的接管提示交给新工具。**没有保留提示也可以发送：

```text
请接手当前项目已有任务。旧工具及其派生任务已停止写入。
先读 AGENTS.md 及适用规则，再核对 MEMORY、CONTEXT、CHECKPOINT 和实际文件现场。
按记录中的精确 task_id、context_revision、handoff_id 核对并认领，不按“最新交接”盲目接手。
如提供接力助手，先 inspect、再 claim，保存接管记录后继续未完成事项。
保留已有修改，重新核验受影响的旧验证；不扩大任务范围及原有授权。
```

只有确实停止旧工具后，才能使用上述“已停止写入”的声明。

### 额度耗尽或突然中断

旧工具无法再生成交接时，直接停止它及其派生任务，在新工具中发送：

```text
请恢复当前项目被中断的任务。旧工具及其派生任务已停止写入，可能没有最终交接记录。
读取 AGENTS.md 及适用规则，对照最后检查点、当前文件、暂存和未跟踪修改核实实际进度。
不能假定检查点之后的修改已验证，也不能用旧记录覆盖当前代码。
如提供接力助手，先 inspect；身份和任务核实一致后，按说明用 claim --recover 保存恢复记录。
任务身份、目标或授权缺失时先核实，不能自行编造。保留已有工作，从已核实的下一步继续。
```

检查点依赖已保存文件，无法恢复未保存编辑器内容或旧工具内部状态。

### 接力助手命令

助手是可选的本地记录工具，**使用助手需要 Node.js >= 18 和 Git**；纯 Shell 初始化不需要它们。
让编程工具执行这些命令即可，不必手工填写所有参数。

```bash
node scripts/handoff.mjs inspect   # 只读核对任务和现场
node scripts/handoff.mjs prompt    # 生成给新工具的接管提示
```

下面是参数示例，任务标识、修订和交接标识须替换为当前文件中的实际值；agent 使用本会话标识：

```bash
# 新工具修改业务代码前认领；只有确认旧工具停止后才传 --source-stopped
node scripts/handoff.mjs claim --agent claude-session-1 --task task-001 --revision 1 --handoff-id relay-001 --source-stopped

# 当前工具准备好结果 JSON 后，保存小步骤进度
node scripts/handoff.mjs save --agent claude-session-1 --input result.json

# 正常交接：保存结果，并使用新的、从未使用过的交接标识
node scripts/handoff.mjs save --agent claude-session-1 --input result.json --handoff-id relay-002
```

`result.json` 由执行工具按真实结果准备，包含已完成、未完成、未验证、阻塞、下一步及验证证据。
缺少交接标识或记录损坏时，核实后按恢复流程使用 `--recover`；不要随意绕过身份冲突。
结果 JSON 格式、恢复和完成命令详见[接力助手说明](docs/HANDOFF-HELPER.md)。
接力不会自动提交、推送或发布，外部操作仍须有实际授权。

## 通过 Agent 接入

在目标项目中打开编程工具，按实际情况复制下面对应的提示词。
新项目可使用一键脚本或 Agent 初始化；已有接力能力的项目优先让 Agent 核对后合并。

### 新项目：首次初始化

```text
请使用 https://github.com/timorpic/agent-handoff，为当前新项目完成首次初始化。

先确认当前项目根目录和已有文件，读取适用的上层及本地规则。
将模板下载到临时目录，核对后初始化当前项目。

要求：
1. 只引入通用规则、工具入口、共享工作流和空白接力文件，不导入模板仓库的身份、维护历史、测试结果或其他项目的信息。
2. 保留已有文件和未提交修改；遇到同名文件先核对，不直接覆盖。项目已有 README.md 时保留，没有时生成空白项目说明。
3. 项目标识根据当前项目核实并统一填写；业务目标、技术栈、架构、部署等未知信息保留待填写，不自行编造。
4. 没有明确活动任务时，CONTEXT 和 CHECKPOINT 保持 draft，不虚构前任、进度、授权或验证结果。
5. 采用统一规则入口，客户端入口只引用；目标是人工切换编程工具后继续同一任务，不增加自动调度或跨工具并发。
6. 核对文件引用、技能链接、忽略规则和实际客户端入口，执行适用检查。
7. 不提交、不推送、不发布。完成后说明生成内容、验证结果和仍需填写的信息。

在上述范围内直接完成，只有影响项目事实或已有内容的关键歧义才向我确认。
```

### 现有项目：补齐已有接力能力

```text
请参考 https://github.com/timorpic/agent-handoff，检查并补齐当前项目已有的任务接力能力。

先确认当前项目根目录，读取适用规则、长期记忆、任务上下文、检查点和相关文档，检查 Git 修改状态。
将参考模板下载到临时目录，先对照现有实现，再做最小必要改动，不整套覆盖或重新初始化。

要求：
1. 以当前项目已确认的需求和有效记录为依据；参考模板只作为改进来源，不自动替换项目约定。
2. 优先复用现有规则入口、记忆、检查点、脚本及工作流。已有等效能力时保留，不创建重复文件或平行事实来源。
3. 保留 README、业务代码、项目身份、历史决策、活动任务、验证证据及用户未提交修改。不把已有记录重置为空白或 draft。
4. 不导入模板仓库的身份、维护历史、测试结果或其他项目的信息。旧验证只有在证据与当前现场仍适用时才能保留为有效结论。
5. 重点检查：新工具能否识别同一任务、核实已有修改、判断验证状态、找到下一步，以及在突然中断后恢复；接管前核实旧工具已停止写入。
6. 统一规则入口和记录职责；客户端入口只引用。合并 .gitignore 时保留业务规则，避免忽略正式文档、共享技能及需跟踪的归档。
7. 不增加自动调度或跨工具并发，不因接入模板而扩大提交、发布或其他外部操作授权。
8. 先简要说明现有能力、缺口及拟修改范围，再在已授权范围内完成补齐，执行适用验证并更新相关记录。
9. 不提交、不推送、不发布。完成后列出实际改动、验证结果、未验证项和剩余问题。

兼容性或记录归属存在关键冲突时向我确认；其余按最小改动原则直接完成。
```
